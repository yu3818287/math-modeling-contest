# 图片要求

图片是评委翻阅论文时最先扫到的内容。一张配色清爽、标注完整的图，能在评委读正文之前就建立印象；一张糊成一团、图例压在曲线上的图，会让整篇论文显得草率。

下面的要求都已经固化在 `assets/mm.mplstyle` 和 `scripts/mmfig.py` 里。**用绘图工具函数出图，不要自己从零写 matplotlib 配置**——凭手感配置几乎必然违反其中某几条。

## 先写图契约，再写绘图代码

写任何一行绘图代码之前，先用一句话回答：**这张图要证明什么结论？**

这不是形式主义。竞赛论文里最常见的绘图问题是"画了图但图没在说话"——数据画出来了，坐标轴也在，但读者看完不知道你想让他看到什么。根源都是画图前没有想清楚这张图的职责。

图契约包含四项：

1. **结论**：这张图要支撑正文里的哪一句判断？写出来。写不出来的图不要画。
2. **读法**：读者应该先看哪里？哪个是主要信息（主曲线、主趋势），哪个是背景？如果一眼看不出主次，说明图的信息组织有问题。
3. **与题目的对应**：这张图服务题目的哪一问、哪一条结论或哪一步推导？
4. **数据来源**：数值来自 `results/` 下的哪个文件。**不允许在绘图脚本里重新硬编码数字**——那等于制造第二个数据源，两处迟早不一致。

想清楚这四项之后，图型基本就自动确定了：要展示趋势和对比就画折线，要展示准确数值就用表格，要展示推导几何关系就画示意图。反过来先选图型、再往里塞数据，几乎必然做出"图很好看但没回答问题"的东西。

一句话概括：**图服务于结论，美观服务于图。**

## 硬性要求

### 1. 图例统一放在右侧，且不与内容重叠

放右侧而不是图内，是因为图内的空白区域位置不确定，图例放进去很容易压住曲线或数据点。右侧是固定位置，不会遮挡。

同时要保证图例**不被画布裁切**——保存时必须用 `bbox_inches='tight'`，否则右侧图例会有一部分被切掉。

**"有没有重叠"不靠肉眼判断，靠几何检测。**`save()` 会自动调用 `detect_collisions()`，逐对比较文字元素的渲染包围盒：

- 两段文字真的压住（重叠面积超过较小者的 50%）→ **直接抛错**，不给保存
- 轻微接触或元素明显越出画布 → 发警告，提示人工看一眼
- 都没问题 → 静默通过

单独调用它可以在调布局时快速迭代：

```python
rep = mmfig.detect_collisions(fig)
print(rep["verdict"], rep["collisions"])
```

### 2. 图内不加标题

不要在 `matplotlib` 里设 `title`，也不要在 LaTeX 里手动在图的上方或下方写图片名称。

原因是：图片的名称由 LaTeX 的 `\caption` 负责生成，带有自动编号（"图 3  不同方案的成本对比"）。图内再加一个标题就会出现两个名称，且编号无法和正文引用对应。

### 3. 不要把多张图拼成一张，尤其不要 2×2 布局

四条曲线放在一个坐标系里对比是可以的；把四张独立的图拼成一张 2×2 的大图不行。

原因是：拼接后每张子图都被缩小，字号随之变小，坐标轴标注和刻度会变得难以辨认。而且拼接图只能有一个 `\caption` 和一个编号，正文无法单独引用其中某一张子图。

如果确实需要展示多个维度的对比，**要么拆成多张独立图分别编号**，要么把多个序列画进同一个坐标系（这才是"对比"该有的样子）。

### 4. 字号与图幅匹配

不允许出现"图很大、字很小"。

具体做法：确定图片在论文中的实际宽度（国赛双栏很少见，通常就是正文宽度约 16cm），然后让导出时的字号在缩放到这个宽度后仍在 9pt 以上。`mm.mplstyle` 里的默认 `figsize` 已经按这个关系配好了。

反例是把 `figsize` 设得很大（比如 20×12 英寸）而字号仍是默认的 10pt——插入论文后会缩得很小，字完全看不清。

### 5. 颜色不使用浅色调，总数控制在 3–4 种

浅色调（浅黄、浅粉、浅青）在白纸上对比度不足，打印成黑白后几乎无法区分。

配色要求：

- 总共 3–4 种颜色，不要更多
- 深浅对比明显，**打印成黑白后仍可区分**（这是很多队伍忽略的——论文可能被黑白打印评阅）
- 色盲友好

`scripts/mmfig.py` 的 `palette()` 返回的就是满足这些条件的默认色板。需要更多颜色时，优先考虑用**线型**（实线、虚线、点划线）和**标记形状**来区分，而不是继续加颜色。

### 6. 图的数据必须与正文和解答严格一致

这一条是硬约束，也是最容易出问题的一条。

正确做法：绘图脚本从 `results/` 读取数据文件，不要在图脚本里重新硬编码一遍数字。重新硬编码就等于制造了第二个数据源，两处迟早不一致。

图表里的数值同时也要能在 `results/numbers.json` 中找到来源，`scripts/check_paper.py` 会检查这一点。

### 7. 不只画数据对比图，还要为推导和流程配图

不要只在处理数据时画图。**公式推导和算法流程如果晦涩，同样要配图**，帮助读者理解。

适用场景：

- 多步推导的中间几何关系
- 算法的迭代流程、状态转移
- 模型的输入输出结构
- 多目标之间的权衡关系（帕累托前沿）

这类示意图用 `matplotlib` 的 patch 绘制即可，`scripts/mmfig.py` 里提供了流程图的辅助函数。不要从网上找图——美赛的提交条款明确要求论文中的每张图要么自己创作、要么在对应位置给出具体引用，用代码生成是最省事的合规做法。

## 绘图工具 API

先把 `scripts/` 和 `assets/` 加入路径，再调用：

```python
import sys, pathlib
sys.path.insert(0, str(pathlib.Path("<skill>/scripts")))
import mmfig

mmfig.use_style()          # 加载 assets/mm.mplstyle，并配置中文字体回退
cols = mmfig.palette()     # 3-4 种非浅色、黑白可辨的配色
```

| 函数 | 用途 |
|---|---|
| `use_style(scale=1.0)` | 加载样式与中文字体。返回字体探测结果；找不到中文字体会**明确警告**而不是静默画方框 |
| `palette(n=None)` | 返回默认色板（3–4 色） |
| `figsize(width_frac=1.0)` | 按论文正文宽度生成合适的画布尺寸，保证缩放后字号仍可读 |
| `save(fig, path, formats=("png","svg"))` | 同时导出 PNG 与 SVG，300dpi、tight，并打印保存路径 |
| `legend_right(ax)` | 把图例放到右侧，并预留空间避免被裁切 |
| `style_axes(ax, xlabel=..., ylabel=...)` | 统一坐标轴、刻度、网格风格 |
| `line_trend` | 折线趋势对比（多方案） |
| `errorbar_plot` | 带误差棒/置信区间的图 |
| `bar_chart` | 柱状图，数值直接标在柱上 |
| `scatter_fit` / `scatter_fit_multi` | 散点 + 拟合线，图中显示 R² |
| `heatmap` | 热力图（非浅色 colormap） |
| `pareto_front` | 帕累托前沿 / 多目标权衡图 |
| `flow_diagram` | 算法流程图 |
| `derivation_diagram` | 公式推导示意图 |
| `figure_report(fig)` | **自检**：报告图例位置、字号、配色数、以及 `collisions` 碰撞结论 |
| `detect_collisions(fig)` | **几何碰撞检测**：文字是否互相压住、是否明显越出画布。返回 `verdict` 与重叠明细 |
| `font_report()` | 报告当前中文字体探测结果 |

`figure_report()` 值得在出图后调用一次——它把上面那些硬性要求变成可检查的输出，比人工肉眼看更可靠。其中 `collisions` 一项来自 `detect_collisions()`，能抓到数值标注互相压住、末端标注压住图例、刻度标签叠在一起这类问题——**这些在缩略图上看不出来，印到纸上才发现**。具体用法与示例见 `scripts/README.md`。

## 输出格式

- **同时输出 `.png` 和 `.svg`**。PNG 用于快速查看与 Word 场景，SVG 是矢量格式，插入 LaTeX 后放大不失真。
- 分辨率 **300 dpi**。
- 论文里引用时，LaTeX 用 `\includegraphics`，让 `\caption` 生成图号与标题。
- **图片必须由代码生成，禁止手工拼图和截图**。手工处理的图无法复现，也无法响应数据更新——一旦结果有修正，就得重新拼一遍，而且很容易漏掉某张。

## 图表分工

同一结果不要同时用表格和图片呈现：

- **表格**：准确数值、详细结果、参数取值
- **图片**：变化趋势、对比关系、结构示意

详见 `writing-style.md` 第六条。

## 出图后自己看一眼

画完图要实际打开图片检查，不要只看"脚本没报错"。需要确认的：

- 中文有没有渲染成方框（字体没配好时不会报错，只会画成豆腐块）
- 右侧图例有没有被裁切
- 坐标轴标注和单位是否完整
- 数值标注有没有互相压住
- 配色在视觉上是否清爽

`scripts/mmfig.py` 的 `save()` 会打印保存的绝对路径，方便据此打开查看。
