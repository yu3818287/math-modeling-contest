# 提交前校验

## 为什么不能照抄"自动核查 21 条"

常见的做法是列一张 20 多条"自动核查 XX 真实性"的清单。这类清单看起来全面，实际执行时几乎一条都不会真正落实——因为其中大部分项（"自动判定因果是否成立""自动检测题意理解是否准确"）**没有任何可执行的判据**，写下来只是许愿。

有效的做法是按**能否机器判定**分成三类，每类配上具体的执行方式：

| 类别 | 数量 | 谁来做 | 判据 |
|---|---|---|---|
| A. 脚本硬校验 | 10 项 | `scripts/check_paper.py` | 有明确判据，可自动判定通过/失败 |
| B. 半自动核查 | 5 项 | 脚本出证据，人做判断 | 脚本能提取出候选，但"是否合理"需要判断 |
| C. 人工自查 | 7 项 | 模型或人逐条读 | 需要理解语义，无法机械化 |

A 类跑脚本；B 类看脚本输出后判断；C 类必须实际读一遍论文。**三类都要做**，跳过 C 类是最常见的失败方式，因为 C 类恰恰是评委最看重的部分。

---

## A 类：脚本硬校验

运行：

```bash
python scripts/check_paper.py paper/main.tex --ruleset cumcm --numbers results/numbers.json
```

| # | 校验项 | 判据 |
|---|---|---|
| A1 | 数字可追溯 | 论文中每个数值都能在 `numbers.json` 里找到对应条目（按 `display` 匹配，`value` 做容差比较） |
| A2 | 正文页数合规 | 国赛 ≤ 30 页；美赛全文件 ≤ 25 页（含摘要页、目录、参考文献、附录、代码） |
| A3 | 摘要页合规 | 国赛摘要连同标题与关键词在一页内且不溢出；美赛 Summary Sheet 为第 1 页 |
| A4 | 全文结构完整性 | 必备模块齐全：标题、摘要、关键词、问题重述、问题分析、模型假设、符号说明、建模求解、结果分析、模型检验、优缺点、参考文献、附录 |
| A5 | 核心检验完整性 | 误差分析、灵敏度分析、稳健性分析三节都存在 |
| A5b | AI 使用声明 | 声明存在，且位置正确——国赛要求位于参考文献**之前**，美赛在正文之后 |
| A6 | 图表编号与引用 | 每个图表都有 `\caption`，编号连续，且正文中至少被 `\ref` 引用一次；无"孤儿"图表 |
| A7 | 公式编号规范 | 重要公式使用编号环境，正文引用使用编号而非"上式" |
| A8 | 三线表合规 | 表格使用 `booktabs` 的 `\toprule`/`\midrule`/`\bottomrule`，不含竖线 |
| A9 | 身份信息泄露 | 摘要页、正文、附录中不出现学校名、姓名、赛区等身份信息（含注释与路径） |
| A10 | 图片文件存在性 | 每个 `\includegraphics` 引用的图片文件确实存在 |

脚本还会顺带报告：参考文献中"列了但未引用"和"引用了但未列出"的条目、`\cite` 与 `refs.bib` 的不一致、以及编译时的 overfull 警告（内容溢出页边距）。

## B 类：半自动核查

脚本能提取证据，但结论要人判断。

### B1 原始数据真实性

**脚本做**：提取论文中所有数值，与 `data/` 原始数据、`results/` 计算结果的数值集合比对。

**人判断**：出现在论文中但脚本无法追溯来源的数字，逐个确认——是真的来自某处计算，还是凭空写的。特别注意"看起来合理"的整数和百分数，它们最可能是编的。

### B2 图表数值匹配

**脚本做**：比对图中标注值与 `numbers.json`、`results/` 中对应数据。

**人判断**：打开图片实际看一眼，确认图上标注的数字与正文引用的是同一个值。图里的数字和正文的数字分处两地，很容易在修改其一时漏改另一处。

### B3 子问题闭环

**脚本做**：列出赛题的小问清单与论文的小节标题，生成对照表。

**人判断**：逐个确认每个小问是否都有明确作答。**漏答子问题是基础扣分项**，而且最容易发生在"题目有隐含子问"时（如"并讨论其合理性"这类附带要求）。

### B4 参数取值依据

**脚本做**：提取论文中出现的参数赋值及其附近的依据说明。

**人判断**：每个关键参数取值是否有合理依据（数据、文献、明确说明的经验值）。无依据的随意赋值是常见失分点。参数表里出现"取 k=0.5"而不说为什么，就是问题。

### B5 模型假设合规

**脚本做**：统计假设条数。

**人判断**：逐条确认假设是否贴合题意、是否过度简化、是否在后文被实际用到。**用不上的假设要删掉**——评委能看出凑数的假设。同时检查有没有"把关键约束假设掉"这种情况（例如"假设所有约束均满足"等于取消了问题）。

## C 类：人工自查

以下必须实际读一遍论文，逐条自问。这些脚本判不了，但恰恰是区分档次的地方。

### C1 题意理解准确性

论文是否精准匹配赛题背景、核心要求、约束条件？

**自问**：把题目重新读一遍，论文解决的问题和题目问的是同一件事吗？有没有场景错配、核心条件遗漏？有没有把题目的某个限定语（"在预算有限的前提下"）在建模时丢掉了？

### C2 逻辑因果真实性

推导逻辑与因果关系是否成立？

**自问**：有没有"因为 A 所以 B"但 A 推不出 B 的地方？有没有强行关联——把两个只是同时出现的数据说成因果关系？结论是否有前文支撑，还是突然出现？

### C3 建模逻辑自洽

假设、推导、求解逻辑是否前后统一？

**自问**：前文假设了线性关系，后文求解时是否还在用线性假设？有没有前后矛盾、逻辑断裂、推导跳跃（某一步说"显然可得"但实际不显然）？

### C4 模型选型适配

模型是否贴合本题场景？

**自问**：有没有堆砌与题目无关的高阶模型？有没有套用通用模板模型（题目是评价问题却硬上一个神经网络）？**一个主模型加必要的辅助模型就够了**，模型与问题的贴合度比模型的高深程度重要。

### C5 求解方法适配

求解方式与模型类型是否匹配？

**自问**：用的是遗传算法，但是否适合这个连续可导问题？用了梯度下降，目标函数是否可导？求解方法与模型类型不匹配会导致结果失效，而且往往不会报错，只是结果不对。

### C6 约束条件纳入

题目的关键约束、限定条件是否全部纳入建模？

**自问**：把题目的约束逐条列出来，对着模型检查。漏掉硬约束（如容量上限、时间窗、预算限制）会让整个模型无意义。

### C7 结果常识合理性

计算结果是否符合客观常识与赛题背景？

**自问**：有没有异常数值？成本为负、概率大于 1、人口增长率 300%、距离超出地理范围——这类错误脚本不会报，但一眼就能看出。**这一条要专门花时间看所有结果数字**，不要只看趋势。

### C8 内容呼应性

摘要、结论、结果、建模过程是否完全呼应？

**自问**：摘要里说的结论，正文里是否真的推导出来了？结论里的数字和结果章节是否一致？有没有摘要写了某个发现但正文完全没提？

### C9 写作同质化

是否有大篇幅 AI 通用套话、万能模板段落？

**自问**：把论文里的题目名称替换成别的题目，还有多少段落成立？成立的那些就是套话，应该删掉或改写成题目专属内容。套话对照表见 `writing-style.md` 第七条。

### C10 文献真实性

参考文献是否真实存在、确实参考过？

**自问**：逐条检查。**不要相信记忆**——如果无法访问原文核实，标注"未核实"让用户自己补，绝不允许编造。美赛官方明确要求"Double-check citations to ensure they are accurate"，国赛也把编造文献视为学术不端。

## 校验结果的处置

- **A 类失败**：必须修到通过。这些是硬指标，不通过就有格式或合规风险。
- **B 类可疑**：逐条确认并记录处置方式（改论文 / 补来源 / 确认无误）。
- **C 类问题**：按严重程度排序，优先修 C1、C2、C5、C6、C7——这五条一旦出问题，是原则性错误，不是文笔问题。

校验完成后，把结果写进交付说明（`README.md`），让用户知道哪些项已确认、哪些项标注为"未核实"。**不要报喜不报忧**——技能的价值在于把真实状态告诉用户，而不是让用户以为一切都没问题。
