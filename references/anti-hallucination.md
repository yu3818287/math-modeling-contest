# 反幻觉纪律与 numbers.json

这一节是技能里最不显眼、但实际收益最大的一部分。它解决的是一个具体问题：**写论文时，模型会写出看起来合理但实际没有算过的数字。**

这不是态度问题，是工作方式问题。写到第三个小问时回忆第一个小问的结果，或者在改写句子时顺手把"12.7%"写成"约 13%"，都会造成论文与代码不一致。而赛事规则对这一点有明确的处罚：

- 国赛：「程序不能运行或**运行结果与论文不符**，都可能会被取消评奖资格。」
- 美赛：评委同样会比对摘要、正文、图表之间的数字；引用不准确会被要求核查。

## 唯一事实源

在 `results/numbers.json` 里登记论文用到的每一个数值。

```json
{
  "_meta": {
    "description": "论文中所有数值的唯一事实源。论文里的每个数字都必须能在这里找到来源。",
    "updated": "2026-09-06T14:20:00"
  },
  "q1.total_cost": {
    "value": 1284500.0,
    "display": "128.45 万元",
    "source": "code/q1.py",
    "figure": "fig_q1_cost_trend",
    "note": "方案 A 的全周期总成本"
  },
  "q2.max_error": {
    "value": 0.047,
    "display": "4.7%",
    "source": "code/q2.py",
    "note": "预测值与实测值的平均相对误差"
  }
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `value` | 是 | 数值本身，用于容差比较 |
| `display` | 是 | **论文中实际出现的字符串形式**，如 `"128.45 万元"`、`"4.7%"`。校验脚本优先按这个匹配 |
| `source` | 是 | 产出该数值的脚本路径，便于复查 |
| `figure` | 否 | 若该数值出现在某张图里，填图的文件名（不含扩展名） |
| `note` | 否 | 这个数字代表什么，帮助后续判断能否改动 |

`display` 字段是关键：论文里写的是"128.45 万元"而不是"1284500.0"，两者必须能对应上。把显示形式和内部数值分开记录，校验才能同时做到"追得到来源"和"和正文一致"。

## 工作顺序

**跑脚本 → 结果落盘 → 登记 numbers.json → 再往论文里写。**

不要反过来：先在论文里写一个印象中的数字，再回头找它出自哪里。找不到的时候，人会倾向于"那就编一个差不多的"，这正是要避免的。

## 三条不可逆的规则

### 1. 校验失败时，改论文或补来源，不许改 json 去迁就论文

`check_paper.py` 报告某个数字无法追溯时，有两种正确反应：

- 论文里的数字写错了 → 按 json 改论文
- 论文里的数字是对的但没登记 → 补登记，并确认它的确来自某次真实运行

**错误反应**是直接把 json 的 value 改成论文里的数字。那样 json 就退化成了论文的副本，失去了校验能力。

### 2. 未经运行的数字，直接标注而不是近似

如果某个数值还没算出来，不要先写一个估计值占位，指望后面替换——后面多半会忘。

正确做法是写 `\textbf{待补：q3 最优解}` 这样的显式占位，并登记到一份待办里。显式占位会在阅读时刺眼地暴露出来，近似值不会。

### 3. 无法核实的内容，标注"未核实"

这条主要针对参考文献和行业结论：

- 文献无法访问或不确定是否存在 → 标注 `% 未核实`，让用户自己补，**不要编一条看起来很像的引用**
- 行业数据没有出处 → 要么找到来源，要么删掉。不要写"据相关研究显示"这种无法追溯的表述
- 仿真数据、实验数据 → 必须由脚本产出。凭空写的仿真数据是最严重的一类问题

编造文献在两个赛事里都属于学术不端，而且很容易被查出来（评委见过大量真实文献，一条假的引文格式再标准也经不起核对）。

## 什么算"需要登记的数值"

需要登记：

- 所有出现在摘要里的数字
- 所有出现在正文结论句里的数字
- 结果表格里的数值
- 图里标注的关键数值
- 参数取值（以及它的来源说明）

不需要登记：

- 章节编号、公式编号、图表编号
- 参考文献年份、页码
- 题目原文里的事实性数字（题目给定的条件，如"共有 100 个节点"）——但这类数字应当来自 `data/` 里的原始数据，不要凭记忆写
- 纯排版用的数字（如"分为 3 类"这类分类数量，若不含计算含义）

边界情况不好判断时，**倾向于登记**。多登记一条的成本很低，漏登记一条的代价是校验失效。

## 与附录代码的对应

国赛要求附录包含完整可运行的源代码，且"程序不能运行或运行结果与论文不符"会被处罚。所以：

- 附录里的代码应当是**实际产出论文结果的那一版**，不是整理美化过的版本
- 提交前把 `code/` 完整复跑一次，确认结果与 `numbers.json` 一致
- 如果重跑结果与记录不符（比如有随机性但没固定种子），要么固定随机种子，要么在论文中说明结果的波动范围

这一点常常被忽略：使用了随机算法（如遗传算法、模拟退火、随机森林）却没有固定随机种子，复跑结果不同，就会直接构成"运行结果与论文不符"。
